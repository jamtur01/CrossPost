# Product

<!-- impeccable:product-schema 1 -->

## Platform

macos

Native macOS app (SwiftUI with AppKit bridging), macOS 15+. Not one of Impeccable's
schema values; recorded as `macos` by the owner's choice. Follow Apple's macOS Human
Interface Guidelines and native control behavior; there is no web or mobile target.

## Users

Primary user is the owner, who reads and posts on Mastodon and Bluesky daily and keeps
CrossPost open as their working window for both networks. Their workflow sets priorities.

Secondary: the public. The app ships as a notarized, Sparkle-updated MIT release from
GitHub, so anyone active on both networks can use it, but features are not built for a
hypothetical broad audience ahead of the owner's needs.

## Product Purpose

Write once, read both. One native window holds a composer and a live feed for each
network, so the user can publish a post or thread to Mastodon and Bluesky together and
follow, reply to, and act on both timelines without switching apps. Success means the
user never needs the networks' own clients for daily posting and reading.

## Positioning

Compose once, publish to both, and read both side by side in a single native Mac
window, while keeping each network's real differences explicit (length limits,
audiences, editing, DMs, live vs. polled refresh) rather than pretending they match.

## Operating Context

- Three-column window: Compose · Mastodon · Bluesky; the composer can be hidden (⇧⌘C)
  without losing the draft.
- Each feed has Home, Notifications, and Messages tabs, with in-place navigation to
  threads and profiles. Mastodon updates live over streaming; both poll about every 60s.
- Replies, quotes, edits, and reports open as sheets scoped to one network.
- Accounts are configured in Settings (⌘,): Mastodon instance + access token, Bluesky
  handle + app password. Credentials live in the Keychain.
- Long-lived window: the app stays open all day alongside other work.

## Capabilities and Constraints

- Cross-posts single posts and threads with images and alt text; validates every post
  against each network's limits before sending, and sends nothing if any check fails.
- Networks publish independently: a failure on one does not block the other. Partial
  thread progress is durable; Retry sends only unsent posts and never duplicates.
- Active drafts (text, images, alt text, audiences, destinations, partial progress)
  survive quits.
- Bluesky posts are always public; the visibility menu applies only to Mastodon.
  Editing exists only on Mastodon.
- Mention autocomplete searches both networks and writes each network's own mention
  format; accounts merge into one person row only by explicit cross-link rules.
- Per-post actions: reply, like, repost/boost, bookmark, delete/pin own posts, who
  liked/reposted, open original. Follow, mute, block from profiles. DMs on both.
- Only http/https links are tappable.
- Mastodon content warnings collapse a post until opened, and sensitive media stays
  blurred until clicked; each reveal lasts for the session and is never saved.
  Bluesky labels use the same covers with Bluesky's default settings: `!warn` and
  `!hide` collapse the post, and adult or graphic media labels blur its media.
- Sandboxed, Developer ID-signed, notarized; Core never imports SwiftUI.

## Brand Commitments

- Name: CrossPost. App icon generated by `scripts/make_app_icon.swift`.
- Quality bar (binding): the UI must hold up next to polished native clients such as
  Ice Cubes and Ivory. Work that reads as a generic or unfinished client fails the bar.

- No testimonials, user counts, press, or benchmarks exist; do not invent them.

## Product Principles

1. The owner's daily workflow comes first; public users get the same app, not a
   separate set of features.
2. Never mislead about what was published where. Per-network outcomes, partial failures,
   and network differences are always stated plainly.
3. Never lose the user's writing: drafts, thread progress, and edits made during sending
   survive failures and quits.
4. Native Mac behavior over custom invention: standard controls, shortcuts, windows,
   sheets, and appearance modes.
5. Reading both feeds should feel as good as the best single-network client.

## Accessibility & Inclusion

- Reading text size setting (Standard, Larger, Largest) applies to post bodies, quotes,
  bios, and DMs.
- Image alt text is supported when composing.
- Light and dark appearances are both first-class.
- No formal conformance standard has been set.
